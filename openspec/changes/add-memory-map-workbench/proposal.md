## Why

内存映射现在有两个独立的窗口：“检查内存映射”（按问题类别看清单）和“内存布局”（按区域或模块看段）。它们暴露出两个毛病：

- **重复且割裂。** 两个窗口各自启动一次后台扫描，各有进度条、取消和结果管理；布局窗口自己没有设置，要先去检查窗口里添加目录和链接文件。用户在两个窗口之间来回切，改完设置还要各跑一遍。
- **布局看起来正常，检查却有问题。** 布局里的"只看有问题的"只覆盖能关联到某个输出段的发现。以下四类发现直接进了总清单，不会出现在任何段行上：用到但没有映射、段声明写法问题、重复映射、链接符号缺失。结果是布局视图显示"没有问题"，而检查窗口里有一串红色条目。

这一条来自对另一份审查报告（`doc/memory_map_review_report.md` 里的 codex 部分）的核实：代码里确实如此（`check.py` 中这四类 `Finding` 直接加入 `result.findings`，不经 `report()`）。

本变更把两个窗口合并成一个“内存映射”工作台：**共享输入设置和一次扫描结果，用页签切换"诊断"和"布局"**，并让两边的问题互相定位。同时给每条发现加上严重程度，让用户先看致命问题。

## What Changes

- **新增"内存映射"工作台**，替换"检查内存映射"和"内存布局"两个菜单项和窗口：
  - 顶部：源码目录、MemMap 头目录、链接文件（沿用现有的目录列表和选择控件）、开始、取消、进度条。一次扫描，两个页签共用结果。
  - **"诊断"页签**：现有检查清单的内容（按类别分组、按类别过滤、导出清单），新增按严重程度过滤。
  - **"布局"页签**：现有布局视图的内容（按区域或按模块分组、按模块／核心／种类过滤、详情、导出）。
  - 页签之间的定位：诊断里的条目可"在布局中显示"（跳到对应的段或执行区域）；布局里选中的段，详情里列出的问题可"在诊断中显示"。没有对应段的发现（如未映射、链接符号缺失）只能在诊断页签里看。
- **布局页签的"只看有问题的"覆盖所有发现**：
  - 能关联到段的，沿用现有关联；
  - 没有对应段行的四类发现，在布局页签顶部显示一行汇总，如"另有 12 条发现不对应某个输出段，在诊断页签查看"，并可一键切换；
  - 过滤开着时，这行汇总照常显示，不被过滤掉，这样用户不会误以为没有问题。
- **严重程度**，每个类别固定对应一级，不按条目动态变：

  | 级别 | 类别 | 理由 |
  |---|---|---|
  | 错误 | 用到但没有映射；链接符号缺失；数据段放在 flash；段声明写法问题（START/STOP 不配对等） | 会导致编译或链接失败，或运行时必然出错 |
  | 警告 | 没有区域接收的段；被多个区域显式选中；核心数据不在本核心内存；不可缓存的段在可缓存内存；重复映射 | 很可能是配置错误，但不一定阻止构建 |
  | 提示 | 未显式放置的段（仅被通配接收） | 静态推断，与链接器实际结果可能不同 |

  - 在 `#if` 分支里的发现（标"可能"）降一级：错误降为警告，警告降为提示，提示不变。
  - 严重程度只用于排序、着色和过滤，不改变检查本身，也不改变 Markdown 导出的条目内容（导出头部新增各级别的数量，条目按类别分组的顺序不变）。
- **只扫描一次**：布局页签与诊断页签读同一个 `CheckResult`。修改设置后需要重新开始扫描，窗口顶部在设置与上次扫描不一致时提示"设置已改动，结果可能过时"。
- **窗口关闭时保存设置**，行为与现在的检查窗口一致（目录和链接文件随工程保存，相对路径）。
- **删除**：旧的两个对话框类及其菜单项。`_CheckWorker` 和目录列表控件合并进新窗口模块，布局窗口对检查窗口模块的反向导入随之消失。
- **不在本变更范围内**：
  - 新增检查或新的发现类别；
  - 芯片设计器里的 `memory_regions` 编辑界面；
  - 编辑放置（那是集成者布局配置，见 `add-memory-layout-view` 的路线）；
  - 读取 `.map` 文件做容量检查；
  - ADS 以外的链接文件格式。

## Impact

- Affected specs：`memory-map-workbench`（新增）。`openspec/specs/` 目前没有 `memory-map-check`、`memory-layout-view`、`link-symbol-needs` 这几份规格（对应的变更尚未归档），所以这里不写成对它们的修改；归档时三者与本变更的关系需要一并整理。
- Affected code：
  - 新增 `ui/dialogs/memory_map_workbench.py`（合并 `memory_map_check_dialog.py` 与 `memory_layout_dialog.py`）
  - `core/memmap/check.py`：新增严重程度的定义（类别到级别的表、`Finding` 的有效级别）；导出头部新增各级别数量
  - `core/memmap/layout.py`：新增"不对应某个输出段的发现"的汇总，供布局页签使用
  - `ui/davinci_main_window.py`：两个菜单项合并为一个“内存映射…”
  - 测试：现有 `tests/ui/test_memory_map_check_dialog.py`、`test_memory_layout_dialog.py`、`test_memory_layout_dialog_symbols.py` 迁移到新窗口；核心层测试补严重程度和汇总
- **兼容性**：
  - 只读，不改变检查结果和生成结果；`CheckResult` 只新增能力，不删字段。
  - 工程文件里保存的设置不变（`memmap_source_dirs`、`memmap_header_dirs`、`memmap_linker_file`），旧工程照常打开。
  - 菜单项变化：工具菜单里“检查内存映射…”和“内存布局…”两项合成“内存映射…”。
- **依赖**：`add-memory-map-check`、`add-memory-layout-view`、`add-link-symbol-needs` 已实现但都未提交、未归档，本变更建立在它们的代码之上。
