## Why

`add-memory-layout-config` 之后，工具里有了完整的布局配置：哪些段放进哪个执行区域，哪个执行区域落在哪块物理存储的哪个窗口。要让它变成能用的东西，还差最后一步：**生成链接文件**，放到集成工程的 `linkedFile` 目录下，让编译器能用。

你确认的做法：配置完成后，选择编译器类型，生成对应的 scatter 或 link 文件。每种编译器的链接文件语法是固定的，因此可以按指定类型生成。

读到的事实：

- 仓库里有每种编译器的厂商样例（`doc/THA6XXX_MC_AS440/.../LinkFiles/`）：ADS（`.scat`）、GHS（`.ld`）、HighTec（`.ld`）、IAR（`.icf`）、Tasking（`.lsl`），每种三个芯片版本；
- 这五种是**不同的内存模型**，不是同一个模型的五种写法：ADS 是带选择器的执行区域；GHS 是 `MEMORY` 加 `SECTIONS` 块；Tasking 的 LSL 有 derivative、group、pack 这类概念。我只读过 ADS，GHS 和其余四种的文件**只看到文件名，没有读过**；
- 生成的链接文件必须提供代码按名字引用的所有符号（`add-link-symbol-needs` 已读出清单），符号写法按编译器而异，对应表已在 `symbols.py` 里（ADS 和 GHS 两种）；注意其中 `startup.c` 是用户手写的代码，本工具不生成它，所以它引用什么由用户决定；
- 现有检查器（`add-memory-map-check`）能把生成的结果再检查一遍。

本变更做**生成**：编译器无关的中间模型，加上 ADS 生成器，生成后用检查器验证。**只做 ADS**。GHS 等其余编译器在界面里置灰并写明"尚未支持"，每个下一个变更各自做：GHS 的符号约定我已读，但它的文件格式我没读，所以不在这一期做。

范围按你的决定限定为 THA6206。OS 自带的 `scatter.scat` 保留，不管它。

## What Changes

- **中间模型**：从布局配置和芯片数据得到一份"链接计划"，与编译器无关：
  - 一组"加载区域"和"执行区域"，每个执行区域有名称、起始（绝对地址，或"接在前一个区域之后并对齐"）、对齐、种类、要收纳的输出段列表；
  - 每个必需区域附带"必须提供的符号"（来自 `symbols.py` 的对应表，按所选编译器）；
  - 界限区域 `<名>_LIMIT` 在这一步自动加上；
  - 链接计划只描述意图，不含任何编译器语法。
- **ADS 生成器**：把链接计划写成 `.scat`：
  - 第一行 `#! armclang --target=arm-arm-none-eabi -march=armv8-a -E -x c`，与厂商脚本一致；
  - `#define` 区域基址，执行区域按顺序，起始用 `AlignExpr(ImageLimit(前一个), 对齐)`，选择器为 `*(.输出段名)`，通配选择器仅在配置要求时写；
  - 必需区域的界限区域用 `EMPTY 0x0 {}` 写出；栈区域用 `EMPTY 大小 {}`；
  - 区域与输出段按名称排序，同样的输入得到逐字节相同的输出（保持指纹稳定）。
- **生成后自检**：生成物立即用现有检查器检查，结果显示在界面里。验收标准：生成的 `.scat` 在"链接符号缺失"和"没有区域接收的段"两类上没有发现。
- **界面**：工作台"配置"页签上新增"编译器"下拉框和"生成链接文件"按钮：
  - 下拉框列出五种编译器，只有 ADS 可选，其余置灰并写"尚未支持"；
  - 生成前显示预览（将要写的文件、覆盖哪个已有文件），确认才写；
  - 写到 `IntegrationProject/linkedFile/Ads/`；已有同名文件时先备份为 `.bak`；
  - 生成失败（缺必需区域的存储、有"待重新放置"或"未放置"的段）不写文件，列出原因。
- **哪些情况拒绝生成**：
  - 存在"待重新放置"的段（切芯片后对不上的）；
  - 必需区域没有落到任何窗口；
  - 一个窗口放不下的情形**不检查**（没有大小信息）；
  - "未放置"的段不阻止生成，但预览里会列出，它们会落入链接器的通配区域或未被接收。
- **对照基准**：生成物与厂商 `LinkerAdsPf.scat` 对照，验证"必需区域名都在"和"各 `.mcal_*` 段的归属一致"（需要读厂商文件，运行前先征得用户同意）。不要求逐字节相同，厂商脚本里有注释、保留区和历史写法。

## Impact

- Affected specs：`linker-file-generation`（新增）
- Affected code：
  - 新增 `core/memmap/plan.py`：链接计划（编译器无关）
  - 新增 `core/memmap/generators/__init__.py`、`ads.py`：生成器接口与 ADS 实现；生成器登记表，说明每种编译器是否可用
  - `core/memmap/symbols.py`：复用已有的编译器符号表，不新增
  - `ui/dialogs/memory_map_config_tab.py`：编译器下拉、生成按钮、预览
  - 测试
- **兼容性**：只在用户点"生成"时写文件；不改变检查和布局；OS 自带 scatter 不动。
- **依赖**：`add-memory-layout-config`（布局配置）、`add-chip-memory-editor`（物理存储分组）、`add-link-symbol-needs`（符号对应表）。
- **不在本变更范围内**：GHS、HighTec、IAR、Tasking 生成器（各自一个后续变更）；容量检查；THA610X 和 THA6412；OS 自带 `scatter.scat` 的处理和与 `Os_link_Lcfg.c` 初始化表的一致性；启动初始化表的检查；`Compiler.h` 与 MemMap 头的生成。
