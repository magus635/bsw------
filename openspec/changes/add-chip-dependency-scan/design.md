## Context

扫描的结果是阶段 1、2 决策和重构的依据，所以宁可多报，也不能漏报；但误报太多又没法逐条确认。下面说明在两者之间怎么取舍。

## Decisions

### 1. 芯片关键字从芯片库推导，用户可以补充

- **完整名称**：取芯片库中每颗芯片的名称（如 `THA6206_LFBGA292`），以及它在 `selectors` 中声明的值（如 `Os_THA6206`）；再加上已加载模块中选择器参数的可选值（xdm 的 RANGE 或 literals），这样能把库里还没有的芯片也算进来（如 `Os_SC300`）。
- **型号片段**：把完整名称按 `_` 切开，取形如 `[A-Z]+\d+[A-Z0-9]*` 的片段，如 `THA6206`、`THA6412`、`SC300`；封装名（如 `LFBGA292`）不计入型号片段。识别封装名的办法：同一芯片名中的第一个片段才算型号。
- **型号族前缀**：取型号片段的字母部分，再加第一个数字，如 `THA6`、`SC3`。一个词如果以族前缀开头，后面跟着至少一个 `[0-9X]`，就算芯片名。按这条规则，`THA610X`、`THA6XXX` 能被识别，而 `THA6_` 不会。
- **用户补充**：用户可以在对话框中补充关键字，随项目保存（`chip_scan_keywords`）。

规则是先宽后窄：族前缀负责不漏报，后面再按“出现位置”收窄，不让误报太多。

### 2. 按出现位置识别，不对整个文件做全文匹配

| 文件 | 识别为发现项的位置 |
|---|---|
| `.xdm`、模板（`.ebt`、`.c`、`.h`、`.m`、`.scat`、`.ld`、`.lsl` 等模板目录下的文件） | XPath 表达式中，与芯片名字符串字面量的 `=`、`!=`，或 `contains`/`starts-with` 调用（字面量包含芯片关键字） |
| C、汇编、链接脚本（用户添加的目录） | 预处理条件 `#if`/`#ifdef`/`#ifndef`/`#elif` 中包含芯片关键字的标识符 |

include 路径、注释和普通字符串中出现的芯片名都不报。注释包括 xdm 的 DESC、C 的 `//` 和 `/* */`。这些地方虽然提到了芯片，但不会影响换芯片后的生成结果。

XPath 表达式的来源：xdm 中 `type="XPath"` 的 `a:da` 属性值，以及模板 `[!…!]` 指令里的内容。

### 3. 隐含默认分支

- **否定判断**：`!= '<芯片>'`、`#ifndef <芯片宏>`、`!defined(<芯片宏>)` 守护的分支，新芯片会直接进入，报在该 IF 行。
- **模板**：用一个栈跟踪 `[!IF]`、`[!ELSEIF]`、`[!ELSE]`、`[!ENDIF]` 的嵌套。如果同一个 IF 链里有芯片判断，又有 `[!ELSE]`，就把 ELSE 所在的行报为“隐含默认分支”。
- **C**：用同样的方法跟踪 `#if`、`#elif`、`#else`、`#endif`。
- **xdm**：ENABLE 条件里没有 ELSE，不需要这一类。

### 4. 疑似写死的芯片数值

只扫描模板目录，包括其中的链接脚本：

- **报告条件**：十六进制常量不小于 `0x10000`，并且出现在指令之外的文本里，即生成文件中原样输出的部分。
- **整理方式**：按文件汇总，每个文件最多列出 50 行，超过的部分只计数。

C 代码不扫描这一类，因为寄存器地址遍布 SDK 和 MCAL，报出来全是误报。

### 5. 资源覆盖

- **选择器参数从哪来**：已加载模块的定义中，被芯片库 `selectors` 声明过的参数。
- **逐个检查的值**：参数定义中的每个可选值。
- **对每个值检查的四项**：
  - (a) 芯片库里是否有芯片声明了这个值；
  - (b) `plugin.xml` 中 `ecuresource` 的 `subderivative` 是否登记了这个值，登记的文件是否存在；
  - (c) 我们按文件名匹配（`resource_file_matches_chip`）到的文件，是否与 EB 登记的是同一个；
  - (d) 模块中直接写出的 `ecu:get`/`ecu:list` 键，在这份资源（芯片 YAML 的 `ecu_resources`，或者 EB 登记的 properties 文件）里是否都有定义。
- **在哪里找 `plugin.xml`**：先找模块定义文件的上两级目录，再找用户添加的目录。只读取，不修改。

### 6. 范围和性能

- **文件过滤**：只扫描以下后缀，不扫描二进制文件。
  - xdm 和模板：`.xdm`、`.ebt`、`.c`、`.h`、`.m`、`.scat`、`.ld`、`.lsl`、`.icf`、`.s`、`.S`、`.asm`、`.mak`、`.txt`。
  - 用户添加的目录：只扫描 C、汇编和链接脚本。
- **大小限制**：超过 2 MB 的文件跳过，并在报告中列出。
- **运行方式**：在后台线程运行，每扫描一个文件更新一次进度，可以取消。
- **结果排序**：按（类别，POSIX 路径，行号）排序，保证每次结果相同。

### 7. 保存

- **保存位置**：`chip_scan_dirs` 和 `chip_scan_keywords` 保存在 `.dpa` 中。
- **路径格式**：相对项目目录的 POSIX 路径，允许 `../`。报告里的路径也按此显示；向上超过 3 级或在另一个盘符时显示绝对路径，以免出现一长串 `../`。
- **旧项目**：没有这两个字段时为空，不影响加载。

## Risks / Trade-offs

- **静态扫描会漏报**：用字符串拼接生成的芯片名，以及通过 `ecu:get` 间接读取的判断，都扫不到。报告开头会写明这一点。
- **族前缀可能误报**：如果某个与芯片无关的宏恰好以 `THA6` 开头又跟着数字，也会被报出来。用户可以按关键字筛选，减少干扰。

## Open Questions

无。EB 仍是正式工具、每年约 2 颗新芯片、插件/MCAL/内核/SDK 都可修改，这三点已由用户确认。
