## Why

`add-memory-map-check` 给芯片 YAML 加了可选的 `memory_regions`：一个平铺的列表，每项有名称、起止、类型（flash/ram）、所属核心、是否可缓存。它够用于检查，但要在界面里把段放进物理存储，有三处不够：

1. **设计器没有编辑界面。** 芯片设计器只有 `flash_size`、`ram_size` 两个文本框。现在 `memory_regions` 只能手写 YAML；THA610X、THA6412 都没有这一节，新增芯片也没有途径补。
2. **平铺模型表达不了"一块存储多个地址窗口"。** 从厂商脚本头部的注释表可以看到（THA6206）：
   - `PFLASH0` 在 `0x08000000`（核本地）、`0x40400000`（可缓存 AXI）、`0x90400000`（不可缓存 AXI）有三个地址窗口，是同一块 flash；
   - `GMU` 在 `0x10000000`（可缓存）和 `0x82000000`（不可缓存）；每块 LMU 各有 NORMAL、DEVICE 两个窗口；
   - 每个核的 TCM 既有核本地别名（`CPUXATCM` 在 `0x0`），也有 AXI 地址（`CPU0ATCM` 在 `0x30000000`）。

   用户把段"放进 GMU"时要选哪个窗口，这个选择就是"缓存还是不缓存"。平铺模型里这些是互不相关的十几个区域，界面没法按"一块存储"来呈现，也没法在选了存储之后只问一个问题"缓存吗"。
3. **没有"待确认"粒度之外的来源记录。** THA6206 的区域是手填的，全部标"待确认"。新芯片会有同样的需求：数据来自哪里（手册、厂商脚本）、哪些已核对，应该能在界面里看到和改。

本变更补上这三点：**在芯片设计器里加"物理存储"页签，数据模型支持"一块存储、多个窗口"，并支持从厂商 ADS 链接脚本的注释表导入**。它是后面两个变更（布局配置、链接文件生成）的前提：没有它，THA610X、THA6412 的右侧没有东西可放。

## What Changes

- **新数据模型（向后兼容）**：`memory_regions` 仍然是平铺列表，保持原样可读可写。在每项上新增三个**可选**字段，用来表达分组：
  - `memory`：这一项所属的物理存储名（如 `PFLASH0`、`GMU`、`CPU0_BTCM`）。同名的项是同一块存储的不同地址窗口。没有这个字段的项，各自就是一块存储（旧 YAML 照常加载，行为不变）。
  - `window`：窗口的用途标签，如 `local`、`normal`、`device`，仅用于显示。
  - `source`：这项数据的来源说明（如 `LinkerAdsPf.scat 注释表`、`THA6206 参考手册 §3.2`），自由文本。
- **设计器新增第六个页签"6. 物理存储 (Memory)"**，模式参照现有的 ECU 资源编辑器：
  - 表格：按物理存储分组，每块存储下列出它的地址窗口；列为名称、起始地址、大小、类型、所属核心、可缓存、来源；
  - 增删改，地址和大小以十六进制输入，输入时校验：数字格式、大小为正、同一芯片内名称不重复；窗口与其他存储的窗口重叠时提示（同一块存储自己的窗口是同一块物理存储的别名，地址不同，不算重叠问题）；
  - 同一块存储的窗口，大小应当一致，不一致时提示（不阻止保存）；
  - 保存时遵守"芯片数据不全只标记、不删除"的约定：缺来源的项标待确认，不丢项。
- **从 ADS 链接脚本的注释表导入**：页签里的"导入…"按钮读取一个 `.scat`，识别头部注释里 `名称 起始 终止/长度 (属性)` 形式的 Memory 表，生成待确认的区域。THA6206 的表就是这个格式；`OS 模板 scatter.scat` 里的表是 `起始 + 长度` 的变体，两种都认。导入结果先预览，用户确认后才合并进芯片，且已有的同名项不覆盖。
- **检查与展示用上分组**：现有的核心、缓存、flash 类型检查继续按"单个窗口"判断，不变；"内存映射"工作台的布局页签里，物理区域一级按存储分组显示窗口，旧芯片（没有 `memory` 字段）显示与现在一致。
- **THA6206 的数据补上分组与来源**：把现有 25 项按存储归组（`memory`、`window`），`source` 写 `LinkerAdsPf.scat 注释表`，仍全部标"待确认"。数据值不变。THA610X 和 THA6412 **不补数据**：没有可靠来源，按"不发明数据"的约定，只提供编辑和导入的途径。

## Impact

- Affected specs：`chip-library`（修改：可选的 `memory_regions` 增加分组与来源字段）；`chip-memory-editor`（新增）
- Affected code：
  - `core/hardware/memory_regions.py`：`MemoryRegionDef` 新增 `memory`、`window`、`source` 三个可选字段；解析与序列化保持旧格式的往返一致；分组函数
  - 新增 `core/hardware/memory_regions_import.py`：从 ADS 链接脚本注释表解析区域
  - `core/hardware/chip_exporter.py`、`chip_database.py`：读写新字段（仅在有值时写出）
  - 新增 `ui/dialogs/memory_region_editor.py`，并在 `chip_definition_designer_dialog.py` 加第六个页签
  - `autosar_configurator/data/chips/THA6206_LFBGA292.yaml`：补分组与来源，版本号按"修复"流程升
  - `core/memmap/layout.py`、`ui/dialogs/memory_map_workbench.py`：物理区域一级按存储分组
- **兼容性**：
  - 新增字段全部可选，旧 YAML 往返不变；`chip_checksum` 对没有新字段的芯片结果不变（避免所有旧芯片被判为"已改动"，现有测试 `test_library_chips_unchanged_and_tha6206_regions` 即是这个保证）。
  - 只有 THA6206 的 YAML 内容变化，需要升 `resource_version` 并写修复历史。
- **不在本变更范围内**：给 THA610X、THA6412 填数据；非 ADS 脚本的导入；容量以外的存储属性（ECC、等待周期等）；由存储区域生成启动代码里的 MPU 配置。
