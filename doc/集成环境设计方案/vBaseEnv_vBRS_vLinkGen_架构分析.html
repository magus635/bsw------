1. 概述

在 Vector MICROSAR 工具链中，广义的 Base Environment（基础运行环境） 由三个紧密耦合的模块共同构成：

模块定位职责
vBaseEnv芯片硬件属性数据库 + 底层驱动模板库负责 CPU 内核（Cortex-R52）初始化、芯片外设（THA6 时钟 / Flash / 看门狗 / GPIO / 复位）底层驱动，以及编译环境配置
vBRS基础运行时系统（Basic Runtime System）硬件无关的主控层：提供 C 语言启动入口、分段内存初始化、main()、OS 默认任务与周期调度的通用框架，通过 BrsHw* 接口操作底层硬件
vLinkGen链接脚本与内存初始化生成器根据 vBaseEnv 的硬件内存区域信息，生成链接脚本与内存清零/拷贝表
严格来说，vBaseEnv 模块本身没有独立的代码生成器，真正执行代码生成动作的是读取 vBaseEnv 参数的 vBRS 生成器和 vLinkGen 生成器。详见 第 6 节。

此外还有面向 PC 端虚拟目标的 VttvBaseEnv：为 CANoe/VTT 虚拟目标环境提供的桩文件（如 _BrsHw.h 仅提供空宏定义 #define BrsHw_EnableHwAccess()）。

2. 架构定位与文件分布

2.1 文件存在两处位置

vBaseEnv 与 vBRS 的源文件同时保留在两处：

位置目录文件名约定用途
组件模板目录DemoComponents/vBaseEnv/、DemoComponents/vBRS/带下划线前缀 _（如 _BrsHw.c）DaVinci / SIP 交付模板，只读基线
应用实例化目录Applications/SipAddon/StartApplication/Appl/去下划线前缀（如 BrsHw.c）实际参与工程编译，包含项目定制修改

2.2 双份文件设计的四个意图

① 隔离“只读基线模板”与“编译工作区”

  • 下划线前缀明确标识未实例化的原始模板，防止构建脚本目录扫描将其误纳入编译；
  • 实例化时，工具（或工程师）将模板拷贝到 Appl/Source/ 与 Appl/Include/ 并去掉 _ 前缀，由 Makefile.project.part.defines 纳入工程编译。

② 允许项目级深度定制，而不污染 SIP 官方包

与 Components/ 目录下禁止修改的 AUTOSAR BSW 静态代码不同，vBaseEnv 属于硬件启动与集成胶水代码，必须按项目单板硬件、多核策略、MPU/TCM 规划进行修改。典型定制差异：

  • 双核启动与外设权限定制（BrsHwEarlyInitPowerOn()）：
    • 应用层 Appl/Source/BrsHw.c：增加 THA6206 解锁 ENDINIT 并置位 CORE_CTRL_ADDR（0xC0020C5C |= 1），在早期由 Core 0 唤醒 Core 1；
    • 模板 _BrsHw.c：保留 Vector 针对 HSM 访问关闭 SMPU（0x40080080 = 0x0）的标准实现。
  • MPU 与 TCM 内存映射定制（ARMStartup_Platform.h）：
    • 模板默认开启 MPU_CODE_REGION、MPU_DATA_REGION、MPU_TCM_REGION 开关（STD_ON），并将 MPU_PERIPHERAL_REGION_START/END 设为 0xB0000000~0xEFFFFFFF，同时包含 THA6412 / THA6206 通用分支；
    • 应用层将上述三个可选 MPU Region 改为 STD_OFF（外设 Region 范围设为 0x0），并针对 THA6206 的 ATCM/CTCM Clone 模式调整 brsTcmBase 基地址。
  • 本地编译环境定制（Makefile）：开发者在 Appl/Makefile 填写本机 HighTec 编译器路径 COMPILER_BASE_WIN 与 LICENSE_SERVER，模板保持干净状态。

③ 保障 SIP 版本升级安全与三方比对合并（Diff & Merge）

SIP 升级工具只覆盖 Components/ 与 DemoComponents/，绝不会直接覆盖 Appl/。本工程示例：

  • 模板目录已随 SIP 升级至 v01.02.00（2025-04-04，新增 THA6412 支持、HSM 分支、BrsHwSoftwareResetECU ENDINIT 复位实现）；
  • 应用目录仍保持在 v01.01.03（2024-05-14）。

通过 Diff 可将官方新版修复按需合并（Merge）进应用代码，同时保护项目组的双核唤醒与 TCM 定制。

④ 支持同一 SIP 下的多应用 / 多镜像复用

一套 SIP 根目录可服务于多个可执行工程（App、Bootloader/FBL、BootManager、HSM 固件等），共享底层模板库，但各自拥有独立的 BrsHw.* / ARMStartup_* 实例，互不干扰（如 FBL 开启 BRS_FBL_EXCEPTIONTABLE_IN_RAM 将向量表重定向到 RAM，App 由 OS 接管中断）。

4. 启动与运行机制详解

4.1 芯片上电到 main() 的完整启动与多核同步机制

启动流程在 ARMStartup_CortexR52.c 与 BrsMainStartup.c 中严格按以下阶段执行：

阶段详解：

  1. EL2 (Hypervisor) 降权到 EL1
    • Cortex-R52 复位后默认进入 EL2（Hyp）模式，入口为 brsStartupEntryHyp；
    • 汇编配置 HACTLR（0x0000B783）允许 EL1 访问控制寄存器，构造 SPSR_hyp = MODE_SVC，将临时向量表 EL1_VectorTable（Reset 向量指向 brsStartupEntry）写入 VBAR 与 ELR_hyp，最后执行 ERET 平滑切换到 EL1。
  2. 多核同步等待屏障（Core Wait Loop）
    • 通过 MRC p15, 0, r0, c0, c0, 5 读取 MPIDR 获取当前核 ID（BRS_READ_COREID）；
    • Core 0 直接向下执行初始化；从核在 coreWaitLoop 中轮询共享变量 BrsHw_CoreStart[CoreId] 是否等于启动魔数 BRSHW_CORE_START_PATTERN（0xAA5555AA），防止在主核完成全局 RAM 初始化前抢跑。
  3. CPU 内核硬件配置（MPU / TCM / FPU / VBAR）
    • 低延迟外设端口与 MPU：使能 IMP_PERIPHPREGIONR，先关 MPU 和 I/D-Cache，遍历清空所有 MPU Region，配置 MAIR0（Normal Non-cacheable 与 Device-nGnRnE），依据 ARMStartup_Platform.h 设置外设/代码/数据/TCM 的 MPU 区域；随后切 MODE_SYS、开启 MPU 及 EL1 Background Region，通过 CPACR 与 FPEXC 开启 FPU；
    • TCM 使能：按当前核 ID 读取 brsTcmBase 数组，写入 IMP_ATCMREGIONR / BTCMREGIONR / CTCMREGIONR（c9, c1, 0~2），为每核使能 ATCM (64KB)、BTCM (192KB/240KB)、CTCM (64KB)；
    • 临时异常向量表绑定：将 ARMBrsHwIntTb_CortexR52.c 中的 intvect_CoreExceptions 写入 VBAR。
  4. Early RAM 清零与各模式栈指针（SP）初始化
    • 遍历 vLinkGen_ZeroInit_Early_Blocks / vLinkGen_ZeroInit_Early_Groups，对当前核内存区域清零（8 字节对齐的 ECC RAM 用 STMIA R3!, {R7, R8} 64-bit 原子写入以初始化 ECC 校验位）；
    • 从 vBrs_Lcfg.c 的 BrsMain_CoreConfig 取出当前核的 StartupStackEndLabel（_STACK_C0_LIMIT / _STACK_C1_LIMIT），依次切换 CPS #MODE_ABT/IRQ/FIQ/UNDEF/SVC/SYS，为各异常模式划分 64 字节栈并设置 SP。
  5. C 语言 PreMain 阶段与多核解锁
    • Brs_PreMainStartup()：
      • BrsHwEarlyInitPowerOn() 在应用层实现硬件级唤醒 Core 1（解锁 ENDINIT 后向 CORE_CTRL_ADDR（0xC0020C5C）置位 1）；模板目录中此处为关闭 SMPU 的实现；
      • BrsHwGetResetReasonStartup() 读取 RCC_RESET_RSTSTAT 判断是否软复位并保存至 brsMain_ResetReason；
    • Brs_ApplicationEntry() 按 StageZero → HardReset → StageOne → StageTwo → StageThree → PowerOn 顺序执行 RAM 清零（BrsHw_AsmMemoryZeroInitLoop() 使用 stm %0!, {r4, r7} 批量写入并执行 dmb）和 ROM→RAM 数据段拷贝；
    • 主核完成后调用 BrsHw_UnlockCores() 将 BrsHw_CoreStart[i] 置为 0xAA5555AA，释放等待中的 Core 1，双核各自进入 main()；
    • main() 中先屏蔽 CPSR 的 IRQ/FIQ，再由 BrsHw_ExceptionTable_Init() 将 VBAR 从 BRS 临时异常向量表切换为 AUTOSAR OS 向量表（_OS_EXCVEC_CORE0_CODE_START / _OS_EXCVEC_CORE1_CODE_START），主核执行 BrsMainInit() 后调用 Os_Init() 与 EcuM_Init() 启动 AUTOSAR 系统。

4.2 硬件看门狗 ENDINIT 保护机制

THA6 关键系统寄存器（时钟 RCC、复位、Flash ECC、引脚驱动强度等）受硬件看门狗写保护：

  • CPUWDT：每核独立，基址 0xF0000000 + 0x400000 * CoreId；
  • SAFEWDT：安全看门狗，基址 0xD0050400。

BrsHw.c 实现完整加解锁协议：

操作函数
CPU ENDINIT 解锁 / 加锁Cpuwdt_Hal_ClearEndinit() / Cpuwdt_Hal_SetEndinit()
Safety ENDINIT 解锁 / 加锁Safewdt_Hal_ClearSafetyEndinit() / Safewdt_Hal_SetSafetyEndinit()

实现细节：读取 PWMAI 判断密码模式是固定密码（0x3333）还是动态 LFSR 密码（动态模式 1 通过多项式移位异或 Cpuwdt_Hal_CalculateDynamicPassword() 计算，动态模式 2 通过异或 0x3F 计算）；向 CEPW/SEPW 写入口令解锁权限，启动/停止 CECNTC/SECNTC 计数器以打开/关闭关键寄存器写窗口，最后置位 PWLOCK 锁定密码寄存器。

4.3 时钟（PLL）与 PFlash 时序初始化

定义 BRS_ENABLE_PLLCLOCKS 时执行 BrsHwPllInitPowerOn()：

  1. PFlash 频率切换预配置（Flash_Hal_PFlashSwitchFreq() / Flash_Hal_CalPFlashTiming()）
    • CPU 升频至 400MHz 前必须调整 PFlash（基址 0xC0100000）访问等待周期，否则高速取指出错；
    • 按目标 400MHz 计算分频系数 bCLKDIV（Flash 时钟 ≤ 100MHz）、读等待 bRDT = 9U 及超时参数 bSTO0/bSTO1，写入 NVM_COMM_CTR->PFCON 与 PF0_CTR。
  2. RCC 与双 PLL 配置（Rcc_Init()）
    • 基于默认 100MHz HSI 将 STM 分频为 25MHz（Rcc_Hal_ConfigStmClk(3U)），利用 64 位 STM 计数器（Stm_Hal_GetValue()）做硬件超时监控；
    • 使能外部高速晶振 HSE 并等待 HSE_READY（Rcc_Hal_EnableHse()）；
    • 配置 System PLL（Rcc_Hal_ConfigSysPll()）与 Peripheral PLL（Rcc_Hal_ConfigPerPll()）：HSE 为参考源，整数模式，refDiv=2、fbDiv=80、postDiv1=1、postDiv2=1，锁定后将 CPU 时钟切至 SYSPLL（400MHz），STM 重新分频（15U）维持 25MHz。
注：本工程集成第三方 MCAL 后，时钟与端口交由 Mcu_Init() / Port_Init() 管理，故 vBrsCfg.h 未开启 BRS_ENABLE_PLLCLOCKS 与 BRS_ENABLE_PORT。

4.4 GICv3 中断控制器与外设辅助接口

  • GICv3 中断管理（ARMBrsHw_CortexR52.c）：通过 MRC p15, 1, %0, c15, c3, 0 读取 IMP_CBAR 获取 GIC 基址；
    • Source < 32（SGI/PPI 私有中断）：操作当前核 Redistributor 寄存器 GICR_*（基址偏移 0x110000 + 0x20000 * CoreId）；
    • Source >= 32（SPI 共享外设中断）：操作全局 Distributor 寄存器 GICD_*，并将 GICD_IROUTER(Source) 路由绑定到当前核。
    • 相关函数：BrsHw_EnableInterrupt() / BrsHw_DisableInterrupt() / BrsHw_TriggerSoftwareInterrupt()。
  • ECU 软件复位（BrsHwSoftwareResetECU()）：先调用钩子 BrsMain_SoftwareResetECU_Hook() 并关中断，解锁 ENDINIT，向 RCC_RESET_SWRSTCON 写 0x1u 触发芯片级软复位，进入 while(1) 等待复位生效。

5.2 关键定制差异示例：为什么必须保留两份文件

以 _BrsMain.c 与 BrsMain.c 为例，官方模板的 Default_Init_Task：

EcuM_StartupTwo();
(void)TerminateTask();

项目实例修改为：

EcuM_StartupTwo();
Rte_Start();          /* 项目定制：显式启动周期性 Runnable */
(void)TerminateTask();
  • 原因：若未配置 BswM 在 EcuM_StartupTwo() 阶段自动触发 Rte_Start()，就需由启动任务显式调用；
  • 两份文件的价值：SIP 从 2024（v02.21）升级到 2025（v02.23）时，若只提供单份编译文件，升级覆盖将导致 Rte_Start() 及 BrsHw.c 中的双核唤醒代码直接丢失，造成系统无法启动或 Core 1 无法运行。

5.3 日常开发与维护建议

  1. 修改代码时：所有针对启动流程、多核唤醒、TCM/MPU 区域、初始化任务的修改，一律在 Applications/SipAddon/StartApplication/Appl/ 下的无下划线文件中进行（修改 DemoComponents/ 下的 _ 文件不生效，因其不在编译列表）。
  2. SIP 升级后：当 DemoComponents/ 版本高于 Appl/ 时，用 Diff 对比两处文件，将新版底层补丁（如 BrsHwSoftwareResetECU() 软复位实现）手动合入 Appl/Source/BrsHw.c。

6.4 DaVinci Configurator 配置流程（三步）

  1. 在 vBaseEnv 模块中选择目标芯片型号
    • /ActiveEcuC/vBaseEnv/vBaseEnvGeneral 的 vBaseEnvTestedDerivativeRef 指向 Tongxin_THA6206；
    • 该节点已由预配置文件填好全部硬件参数（CORTEX_R52、2 核、400MHz、6 CAN / 8 LIN / 9 SPI / 1 Ethernet，以及各核 ATCM/BTCM/CTCM、GMU、LMU、PFLASH 的首地址、大小、ECC 对齐 4/8 字节）。
  2. 在 vBRS 模块中配置运行环境与硬件外设处理策略
    • vBRSGeneral：vBRSExecutionInstance = Application、vBRSFirstInstance = true、vBRSEnableMultiCoreSupport = true、vBRSEnableCoreSpecificVLinkGenConfig = true；
    • vBRSHwConfig：vBRSOscClock = 25MHz、vBRSTimebaseClock = 400MHz、vBRSPeriphClock = 25MHz，关联 McuClockReferencePoint_0；因已有 MCAL，vBRSEnablePLLClocksHandling、vBRSEnablePortHandling、vBRSEnableWatchdogHandling 均设为 false；
    • vBRSMemoryInit：RAM 清零填充值（默认 0x0）及 64-bit 初始化模式。
  3. 执行 Solving Actions（一键联动配置 Os 与 vLinkGen）
    • 在 Os 中自动创建每核 Default_Init_Task / Default_Init_Task_Trusted，按 vBRSPeriphClock 计算 OsCounterTicksPerBase；
    • 在 vLinkGen 中按 Tongxin_THA6206 激活存在的内存区域，并按核创建启动栈段组 STACK_C0、STACK_C1；
    • 检查工程中是否存在 Mcu/Port/Wdg/EcuM/Rte，自动开关 BrsHw 硬件初始化与 EcuM/SchM Stub 开关。

7.1 与工程 ECUC 配置的关系

  1. 只读基线继承：vBaseEnv_bswmd.arxml 通过 <PRECONFIGURED-CONFIGURATION-REF> 引用 /MICROSAR/vBaseEnv_Pre；
  2. 动态加载与持久化：每次加载工程（Project Load）、执行 Project Update 或添加 vBaseEnv 模块时，DaVinci Configurator 都会将预配置内容动态应用到内存模型并设为只读锁定（GUI 中呈灰色不可改），保存工程时同步固化到 StartApplication_vBaseEnv_vBaseEnv_ecuc.arxml；
  3. 用户只需“二选一”引用：在 vBaseEnvTestedDerivativeRef 中选择 Tongxin_THA6206（或 Tongxin_THA6412）。
直观证据：对比两文件的容器 UUID（如 vBaseEnvGeneral 的 f547b67a-…、Tongxin_THA6206 的 fb13c10d-…）100% 一致，证明工程 ECUC 配置正是从该预配置派生。

7.3 下游模块如何使用

  1. vLinkGen.jar：选中 THA6206 后自动识别 CORE2/3_*、PFLASH2/3 不可用，只启用 THA6206 拥有的内存块；因 CORE0/1_ATCM 标记 EccAlignment = 8，生成的 vLinkGen_Lcfg.c 将 ATCM 对齐属性设为 8，指导启动代码用 64-bit 写入指令初始化 ECC RAM，防止触发 ECC 硬件异常。
  2. vBRS.jar：校验 PLL 时钟不超过 400MHz；限制可勾选的 CAN/LIN/SPI 通道数不超过硬件上限；输出芯片宏、核数、核架构到 vBrsCfg.h 与 Makefile.config.generated。

7.4 逻辑命名空间绑定机制：/MICROSAR/vBaseEnv_Pre 如何解析

vBaseEnv_bswmd.arxml 中没有写物理文件名 vBaseEnv_THA6_pre.arxml，只写 /MICROSAR/vBaseEnv_Pre。因为 AUTOSAR ARXML 不采用 C 语言 #include "文件名" 的物理引用方式，而是采用“目录自动扫描 + 逻辑命名空间（ARPath）合并”机制：

  1. ARPath 拼接：元素全路径由外层 <AR-PACKAGE> 的 <SHORT-NAME>（MICROSAR）与该元素 <SHORT-NAME>（vBaseEnv_Pre）拼接为 /MICROSAR/vBaseEnv_Pre；
  2. DaVinci 定位物理文件：
    • .dpa 工程文件第 37 行 <SIP>.\..\..</SIP> 定位到 mcuapp/ 根目录；
    • 启动时递归扫描 <SIP>/Components/*/BSWMD/ 与 <SIP>/DemoComponents/*/BSWMD/ 下所有 .arxml（含 Tongxin_THA6/vBaseEnv_THA6_pre.arxml），将同属 <SHORT-NAME>MICROSAR</SHORT-NAME>（包 UUID 均为 ff55d029-386d-43a2-b3c2-dfef4c7a5e36）的节点合并到同一内存模型树 /MICROSAR；
    • 合并后，/MICROSAR/vBaseEnv_Pre 引用即可绑定到 vBaseEnv_THA6_pre.arxml 定义的节点。
  3. 设计目的：解耦通用模型与芯片专属数据，实现跨芯片平台的插件化复用 —— vBaseEnv_bswmd.arxml 对 TC3xx、RH850、S32K、THA6 完全通用，只需在不同芯片子目录放入同名 /MICROSAR/vBaseEnv_Pre 节点文件。

7.5 Vector 制作 pre.arxml 的流程

站在 Vector 平台研发团队（PES）角度，制作该文件不是手工敲写 XML，而是基于 BSWMD 模型通过 DaVinci Configurator 可视化建模并导出：

  1. 第一步：提取平台硬件规格——从芯片手册梳理 CPU/外设规格与物理内存映射表、每块 RAM 的 ECC 对齐要求（ATCM 为 64 位 ECC → EccAlignment = 8，其余为 32 位 ECC → 4）；
  2. 第二步：可视化录入（利用 Clone 机制）——创建基准型号 Tongxin_THA6206，GUI 填核数/主频/通道数及 16 个内存块；右键 Duplicate 生成 Tongxin_THA6412，改核数为 4、BTCM 240KB、补 CORE2/3_*、GMU1_*、PFLASH2/3；建立平台级内存区域全集列表；故意留空 vBaseEnvTestedDerivativeRef 供客户选择；
  3. 第三步：导出 Preconfiguration——将顶层包从 /ActiveEcuC/vBaseEnv 重定向为 /MICROSAR/vBaseEnv_Pre，剔除工程级标签，保存为 _pre.arxml（与工程 ECUC 结构除头部包装外几乎一致）；
  4. 第四步：配套制作 vBRS_THA6_pre.arxml——导出 ARM 指令集、400MHz、25MHz 外设时钟、FPU 至 /MICROSAR/vBRS_Rec，评估板晶振参数至 /MICROSAR/vBRS_Pre，随 SIP 发布。

8. 变体（Variant）机制

在 Vector MICROSAR 体系中，“变体”从底向上分为三个层次。

8.1 硬件衍生型号变体（Derivative Variants）

解决同系列不同芯片型号（双核 vs 四核、Flash/RAM 容量差异）的切换，机制为“超集预配置 + 单点引用切换 + 宏条件编译”：

  1. 在 vBaseEnv_THA6_pre.arxml 的 vBaseEnvDerivativeInformation 下列出 Tongxin_THA6206、Tongxin_THA6412，并在 vBaseEnvGeneral 列出全家族内存区域超集；
  2. 工程中只需修改 vBaseEnvTestedDerivativeRef 指向具体型号；
  3. 联动生成：
    • 链接器层面：vLinkGen 自动计算每个硬件内存区的 Calculated Availability（选中 THA6206 时，CORE2_ATCM/BTCM/CTCM、CORE3_ATCM/BTCM/CTCM、GMU1_NORMAL/DEVICE、PFLASH2_NORMAL/PFLASH3_NORMAL 自动变为不可用）；
    • 配置宏：vBrsCfg.h 生成 #define BRS_DERIVATIVE_Tongxin_THA6206，Makefile.config.generated 生成 BRS_CPU_CORE_AMOUNT = 2；
    • 静态源码：通过 #if defined (BRS_DERIVATIVE_Tongxin_THA6206) / #elif defined (BRS_DERIVATIVE_Tongxin_THA6412) 切换寄存器地址、外设时钟或 TCM 初始化范围。

8.2 多镜像/执行实例链接变体（vLinkGen Linker Variants）

解决同一颗芯片上多个可执行程序（BootManager、Bootloader/FBL、Application、FlashDriver）的内存布局与启动代码变体：

  1. 定义执行实例变体：vLinkGenVariant_FirstExecInst（isFirstExec = true，上电复位后第一个执行，如 BootManager 或无 BM 时的独立 App）与 vLinkGenVariant_DemoAppl（isStandardAppl = true，由前序实例跳转进入的后续实例，如带 BM 的 App 或 FBL）；
  2. 按变体裁剪或共用段：
    • 仅限首个实例：Brs_Startup_Code（上电汇编启动 + RAM 清零逻辑）只引用 FirstExecInst，后续实例无需重复硬件复位向量；
    • 多实例共用：Brs_ApplicationEntry（应用入口跳转点）、Brs_Shared_Var（跨实例复位原因 brsMain_ResetReason）、各核启动栈 STACK_Cx 同时引用两个变体；
  3. 变体专属地址覆写与多文件生成：同段在不同变体可映射到不同 Flash 扇区；vLinkGenFileGeneration = ONE_FILE_PER_VARIANT 时为每个变体生成独立链接脚本（如 vLinkGen_Template_FirstExecInst.ld）；vBRSVariantUsageOfvLinkGen 选择当前工程使用的链接变体，Makefile.config.generated 输出对应 BRS_LINKER_COMMAND_FILE_POSTFIX。

8.3 软件配置变体（ECUC Pre-Compile / Post-Build Variants）

解决同一份软件适配不同车型/高低配的参数变体：

  1. BSWMD 元模型声明：<SUPPORTED-CONFIG-VARIANTS> 声明模块支持的配置阶段（基础设施模块 vBaseEnv 仅支持 VARIANT-PRE-COMPILE，通信/诊断/EcuM 等支持 VARIANT-POST-BUILD）；每个参数通过 <SD GID="DV:postBuildSelectableChangeable"> 标记是否允许跨变体设不同值；
  2. DPA 工程级开关：StartApplication.dpa 中 <PostBuildLoadableSupport> / <PostBuildSelectableSupport> 控制是否开启 Post-Build 变体；开启后可定义多个变体（如 Variant_High、Variant_Low），ECUC 通过 <VARIATION-POINT> 记录参数差异，生成多套后缀配置结构体（如 EcuM_Config_Variant_High）；
  3. 启动阶段运行时变体选择（EcuM + vBRS 协同）：配置多个 Post-Build Selectable 变体时，main() 调用 EcuM_Init() 后，EcuM 调用钩子 EcuM_DeterminePbConfiguration()（读硬件编码引脚或 NVM 车型配置字），动态返回当前车型的 EcuM_GlobalConfigRootType，在同一镜像中动态激活对应 BSW 配置。
