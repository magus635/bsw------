### 一、模板查找机制（3 级优先级查找）

当对某个模块（如 `Dio` 或 `Can`）触发代码生成时，`CodeGenerator._discover_template_types()` 会按**优先级从高到低**在以下 3 个位置查找代码模板：

| 优先级 | 模板来源 | 路径位置 | 说明 |
| :--- | :--- | :--- | :--- |
| **1（最高）** | **工程覆盖层模板** (`project_template_dir`) | `<工程根目录>/templates/<ModuleName>/` | 用户为该工程单独定制/覆盖的模板，优先级最高。 |
| **2** | **模块包自带模板** (`package_template_dir`) | 模块包的 `manifest.templates` 目录 | 随 BSW 插件包自带的生成模板（直接是模块目录，内部不含 `<ModuleName>` 子目录）。 |
| **3** | **全局用户模板** (`user_template_dir`) | 用户全局配置的模板目录 | 可选的全局 fallback。 |

> **关键判定**：如果这 3 个位置**均未找到任何模板**，生成器会判定该模块为 `SKIP`（跳过），日志记录：  
> `No templates found for module <ModuleName> — skipped`，因此不会生成任何代码文件。

### 二、为什么 EB 能生成，而 DaVinci 无法生成？

这是由 **Vector DaVinci 与 EB Tresos 两种工具链的底层代码生成架构差异** 决定的：

#### 1. EB 模块能够生成的原因
- **EB Tresos 采用开放的文本模板机制**：
  EB 的每个插件目录（如 `Dio_TS_T16D27M10I0R0`）下，原生就自带了一个 **`generate_PB/`**（或 `generate/`）目录。
- **自动识别与加载**：
  导入 EB 插件时，系统扫描到该目录，自动在 `module.json` 中配置了 `templates: "generate_PB"`。
- **内置 EB 模板引擎**：
  工具内置了完整的 `EBTemplateEngine`，能够自动解析 EB 模板中的 `[!IF ...!]`、`[!LOOP ...!]`、`[!SELECT ...!]` 语法，因此 EB 模块能一键直接生成出完整的 `.c` 和 `.h` 代码。

#### 2. DaVinci 模块无法生成的原因
- **Vector DaVinci 官方不提供开放的文本模板**：
  Vector MICROSAR 的生成器是**闭源编译型程序**（封装在 `Generators/*.jar` 的 Java 程序或可执行文件中），其 SIP 交付包的 `Components/*/BSWMD/` 目录下**只有 ARXML 描述文件，根本不包含文本形式的生成模板（.tpl / .xpt）**。
- **包内无模板路径**：
  导入 DaVinci SIP 时，生成的模块包 `module.json` 里没有 `templates` 字段（`package_template_dir` 为 `None`）。
- **找不到模板而跳过**：
  由于本地工程的 `templates/<ModuleName>/` 默认是空的，生成器在 3 级查找中均找不到该模块的模板文件，因此判定无需生成，直接跳过。

> **提示**：如果为 DaVinci 模块提供了模板（例如工具源码中已在 `template_packs/davinci/` 下为 `Det` 和 `Crc` 预置了 DaVinci 格式模板），只需将其复制到工程的 `templates/<ModuleName>/` 目录下，DaVinci 模块同样可以立即生成代码！

### 三、生成的代码存放在哪个位置？

生成代码的存放路径区分**整工程生成**与**单模块生成**：

#### 1. 批量整工程代码生成（菜单：`Project ➔ Generate Code`）
无需弹窗选路径，系统会统一输出到当前工程的 **`gen/`** 目录下：
```text
<工程根目录>/
  ├── gen/
  │    ├── Dio/
  │    │    ├── include/
  │    │    │    └── Dio_Cfg.h
  │    │    └── src/
  │    │         └── Dio_Cfg.c
  │    ├── Mcu/
  │    │    ├── include/
  │    │    └── src/
  │    ...
```
*(注：如果当前启用了多变体 Post-Build Variant，则会在模块目录下多一层变体子目录，如 `gen/Dio/<VariantName>/include/...`)*

#### 2. 单模块独立代码生成（菜单：`Module ➔ Generate Code for Current Module`）
- 界面会弹出目录选择框，让用户自由选择目标根目录 `Output Directory`。
- 生成器会在选定目录下自动按模块创建子目录：
  - 头文件输出到：`<选定目录>/<ModuleName>/include/<ModuleName>_Cfg.h`
  - 源文件输出到：`<选定目录>/<ModuleName>/src/<ModuleName>_Cfg.c`
  - 散列脚本/嵌套文件：保留原模板的相对子目录层级。


## 模块包自带模板的定义
**“模块包自带模板”（`package_template_dir`）** 指的是**随 BSW 模块插件包/驱动包本身存放在一起的代码生成模板目录**。

下面以具体的文件树结构分别说明 **EB 模块** 和 **DaVinci 模块** 的实际位置：

---

### 1. EB 模块的具体位置（以 Dio 模块为例）

当你把 EB 工程导入为当前工程时（例如 Copy 模式），EB 插件会被存放在当前工程的 `modules/eb/` 下：

```text
你的工程根目录/
  ├── config/
  │    └── Dio.arxml                         <-- 你的配置数据 (Active)
  ├── modules/
  │    └── eb/
  │         └── Dio_TS_T16D27M10I0R0/        <-- EB 模块插件包目录
  │              ├── plugin.xml              <-- 插件清单
  │              ├── config/
  │              │    └── Dio.xdm            <-- 参数定义元模型
  │              │
  │              └── generate_PB/            <-- ★★★ 这就是“模块包自带模板”目录！ ★★★
  │                   ├── Dio_Cfg.h          <-- EB 文本模板文件 (内含 [!IF...!] 语法)
  │                   ├── Dio_Cfg.c
  │                   ├── Dio_PBCfg.c
  │                   └── Dio.m              <-- 宏定义脚本
```

- **工具如何找到它**：
  在加载 EB 插件时，系统识别到插件根目录下有 `generate_PB` 文件夹，便会自动将其注册为该模块包的模板目录。
- **如果在 Link 模式下**：
  插件没有复制到工程内，此时该目录直接指向你原始 EB 安装路径下的插件目录，例如：  
  `D:/EB/tresos/plugins/Dio_TS_T16D27M10I0R0/generate_PB/`。

---

### 2. DaVinci 模块为什么没有这个目录？

当你导入 DaVinci SIP 工程时，DaVinci 模块被保存在 `modules/davinci/` 下：

```text
你的工程根目录/
  ├── config/
  │    └── Can.arxml                         <-- 你的配置数据
  ├── modules/
  │    └── davinci/
  │         └── Can/                         <-- DaVinci 模块包目录
  │              ├── module.json             <-- 包清单描述
  │              ├── config/
  │              │    └── Can.arxml          <-- 模块定义
  │              └── base/
  │                   ├── Can_Rec.arxml      <-- 推荐基线配置
  │                   └── Can_Pre.arxml      <-- 前置基线配置
  │              （这里 Vector 官方只有 ARXML，没有模板文件夹！）
```

- 在 `module.json` 清单里，没有 `"templates"` 这一项，因此生成器读取到的 `package_template_dir` 为 `None`。

---

### 3. 如果想让 DaVinci 模块也能生成代码，应该放在哪里？

有两种最直接的做法：

#### 做法 A：放在工程级覆盖模板目录（最推荐，无需改动任何包配置）
在当前工程根目录下创建 `templates/<模块名>/` 文件夹，将模板放进去：
```text
你的工程根目录/
  ├── templates/
  │    └── Can/                              <-- ★★★ 工程级模板目录 ★★★
  │         ├── Can_Cfg.h.tpl                <-- 支持 Jinja 风格或 EB [! ... !] 风格
  │         └── Can_Cfg.c.tpl
```
*(生成器优先级第 1 级就是找这里，只要这里有模板，立刻就能生成到 `gen/Can/` 下)*

#### 做法 B：打包进模块包（成为包自带模板）
在 `modules/davinci/Can/` 下新建 `templates` 文件夹并放入模板，然后在 `modules/davinci/Can/module.json` 中加上：
```json
{
  "module": "Can",
  "templates": "templates",
  ...
}
```
这样它就拥有了与 EB 类似的“模块包自带模板”。
