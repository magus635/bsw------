芯片定义设计器使用说明

芯片定义设计器用来维护一颗 MCU 的全部硬件数据，保存为一个芯片 YAML 文件。项目选中这颗芯片后，硬件映射、配置界面的参数约束和代码生成都从这个文件取数，不再依赖 EB Tresos 插件里的 .properties 文件。

01打开方式

设计器有三个入口。保存成功后，三个入口都能马上用上新芯片，不需要重启软件。

主窗口菜单 Tools › Chip Definition Designer...

已打开项目时自动载入项目当前的芯片，ECU 资源页可以扫描项目模块所需的键。保存后状态栏提示“芯片库已更新”，界面约束随之刷新。

新建项目向导 · 芯片页 🆕 新建芯片...

保存后关闭设计器，向导刷新芯片列表并自动选中刚保存的芯片。

硬件映射向导 · 芯片页 ➕ New Chip...

保存后关闭设计器，向导刷新芯片下拉框并自动选中刚保存的芯片。

窗口分四个区域。上方是克隆模板，中间是五个页签，下方是状态栏和保存按钮。

  • B五个页签分别编辑芯片 YAML 的不同段落，详见下文。切换页签不会丢失未保存的修改。
  • C左侧状态栏显示最近一次操作的结果，例如导入了多少个键。点保存才会写文件，导入和推导只改界面里的数据。

新建一颗芯片的步骤

  1. 用 A 区克隆同系列的芯片，或者直接在默认值上修改。默认型号是 NEW_MCU_SERIES。
  2. 在 1. 基础信息 填写型号、系列、封装和描述，并在“芯片选择器”表格里写上本芯片在各模块选择器参数上的取值。
  3. 在 4. ECU 资源 点 📥 导入 .properties…，选中厂商的属性文件，可以多选。
  4. 回到 1. 基础信息。如果页面提示核信息与 ECU 资源不一致，点 用 ECU 资源覆盖表单。
  5. 在 2. 外设 点 🔄 从 ECU 资源推导外设，再手工补上推导不出来的类型，例如 PWM 和 ICU。
  6. 在 3. 引脚复用矩阵 点 📂 从 Excel / CSV 导入引脚表 (Import...)，修正标红的重复引脚。
  7. 在 5. 预览与导出 检查 YAML 内容和一致性提示，然后点 💾 保存到芯片库 (Save to Database)。

五个页签

1基础信息Basic Info

  • 芯片型号 (Name)*：必填，只能用字母、数字和 _ . -，不能以符号开头。型号同时是文件名 <型号>.yaml。
  • 芯片系列、封装规格、描述：在芯片列表和向导里显示，不参与生成。
  • CPU 核数、可用核心列表、主核：改核数会自动重填 CORE0 到 CORE<n-1>。模板只读 ECU 资源里的核信息，所以两边不一致时以 ECU 资源为准，页面会给出提示，点 用 ECU 资源覆盖表单 即可对齐。
  • 芯片选择器 (Selectors)：每行一个 模块.参数 和取值，例如 Resource.ResourceSubderivative 取 THA6412_BGA516，Os.OsResourceSubderivative 取 Os_THA6412。用 增加一行 和 删除所选行 编辑。格式不对、取值为空或重复的行会阻止保存。

2外设Peripherals

  • 左侧是外设类型，带实例数和对应模块。新增类型 可以从硬件映射规则里选，也可以直接输入新的类型名。引脚类型不在这里编辑。
  • 右侧是实例表，列出 resource_id、display_name 和每个属性。映射规则会读取的属性列名带 *，缺值时标黄，页底提示“硬件映射向导将拿不到 X”。
  • 实例操作：增加实例 复制实例 删除实例 批量添加… 增加属性 删除属性。批量添加按前缀、起始编号和个数生成，例如 CAN0 到 CAN5，以 _id 结尾的属性自动填编号。
  • 单元格类型按输入推断：0x0C 存为整数 12，true 存为布尔，逗号分隔存为列表。

🔄 从 ECU 资源推导外设 按第 4 页的硬件常量生成实例，编号直接用厂商的硬件单元名。已有实例且内容会改变的类型，会先列出来请你确认，默认选“否”，选“否”就什么都不改。只新增类型时不弹窗。

外设类型实例取自对应模块
can_controllerCan.HwUnitNode，例如 CAN_CONTROLLER_00Can
adc_unitAdc.HwUnitId；通道数取 Adc.AdcChannels_Adc<n>Adc
spi_unitSpi.HwUnitListSpi
eth_controllerEth.MaxControllers；速率和接口取 Eth.EthSpeed、Eth.EthPhyIntfEth
wdg_unitWdg.WdgInstanceWdg
clock_sourceMcu.SysPllClkMaxFrequency、HSEClkFrequency、HSIClkFrequencyMcu
gpt_channelBasetimer.HwUnitList，与 Gpt 插件读取的键相同Gpt
lin_channelAsi.AvailableHWUnit，与 Lin 插件读取的键相同Lin
intc_sourceIntc.IntSrcClass 下各类、各子类的 IntName 和 IntID；每个核私有的类标为不可配置Intc

没有名称列表时按数量键生成编号，例如 Can.MaxModules 为 2 时生成 CAN0 和 CAN1。厂商文件里没有的属性只填协议默认值：CAN 标称 1 Mbit/s、SPI 20 MHz、LIN 20 kbit/s。报文对象数、看门狗超时范围这类芯片参数不会被编造。中断源的向量号取自 IntID，厂商文件里重名的中断只保留第一个。

3引脚复用矩阵Pinout & Mux

  • 📂 从 Excel / CSV 导入引脚表 (Import...) 按表头识别列，中英文表头都认，例如“端口 / Port”“引脚号 / Pin”“引脚名称 / Signal”“方向 / Direction”“复用功能 / AF”。
  • ➕ 添加引脚 (Add Pin) 和 ➖ 删除选中 (Delete) 逐行编辑。“端口过滤”只显示某个端口，右侧统计端口数和引脚数。
  • 表格有五列：端口、引脚号、引脚名称、默认方向、复用功能。复用功能用逗号分隔，带模式号时写成 2:CAN0_TX。
  • 同一端口下重复的引脚号会标红，保存时被拦下。引脚表为空时保存会再问一次。
  • 🔄 从 ECU 资源生成引脚表 按 Port.AvailablePortsID、Port.Port<N>_AvailablePins 生成端口和引脚，复用功能取 Port.InputModesXDM<hex> 与 Port.OutputModesXDM<hex>（<hex> 为端口号×16+引脚号的十六进制），只读端口只列输入功能。已有引脚且内容不同时先列出数量并询问，默认“否”。
  • 引脚表的端口与 Port.AvailablePortsID 不一致时，页面上方和预览页都会给出提示（缺少哪些端口、多出哪些端口），只提示不拦截保存。
  • 每个端口会变成一个 gpio_port，每个引脚变成一个 gpio_pin，供 Port 和 Dio 模块的硬件映射使用。端口号取端口名末尾的数字（P10 → 10；以 A–P 结尾的旧名字按字母换算），PortPinId 与 Dio 通道号都是端口号×16+引脚号，端口里缺的引脚不生成容器。

4ECU 资源ECU Resources

这一页编辑模板和 xdm 中 ecu:get()、ecu:list() 读取的常量，例如核数、主核、ISR 触发方式和各外设的硬件单元表。键名与 .properties 文件里的完全相同，形如 <模块>.<名字>。

  • 📥 导入 .properties… 可以多选文件。全部键按第一个点分到模块里并入，后导入的文件覆盖先导入的同名键，没有点的键会被跳过。
  • 左侧是按模块分组的键树，可以新增模块、新增键、重命名和删除。模块名不能含点，键名可以，例如 SyncGroup.Master.SARADC0。
  • 右侧编辑值，点 应用 (Apply) 后才写入。标量的类型自动推断，勾选 按字符串保存 (Keep as string) 可以保留 007 这类文本。列表可以逐项增删和排序，用 转为标量、转为列表 互换。长字符串用多行编辑，前导空格原样保留。
  • 区间视图 (Range view) 把长列表显示成“下标区间 / 值”。例如 992 项的 Os.IsrTriggerMethodList 只有几行，有缺口或重叠时会被拒绝。
  • 搜索与过滤：按键名或值搜索，可只看“待填写”或“有问题”的条目。
  • 扫描项目模块所需键 和 从插件目录扫描所需键… 列出 xdm 和模板里以字面量引用、本芯片还没有值的键，勾选后加入为黄色的待填写条目。拼接出来的键扫不到，列出的键也不一定都需要。
  • 页底显示一致性检查结果，只提示，不阻止保存。规则包括核数等于 AvailableCores 的个数、OsResource.MasterCore 必须写成 OS_CORE_ID_<n>。

修复已有芯片

已有芯片的数据需要更新时（新版 MCAL 的 .properties、插件需要新的键、待确认项已经核实），用芯片修复向导，不要克隆后再改名。向导以 ecu_resources 为准：先改 ECU 资源，再由它同步外设、核与引脚表。向导不会改芯片名，缺失或待确认的数据只标记、不删除。

有三个入口：

  • 主窗口 Tools › 修复芯片...：预选当前项目的芯片。
  • 设计器顶部的 🔧 修复此芯片…：只在编辑芯片库里的已有芯片时可用。有未保存的修改时会先询问，修复后重新载入这颗芯片。
  • 项目属性里"资料不完整"提示旁边的 修复…：预选这颗芯片。
页做什么
1. 选择芯片显示版本、完整性问题、最近一次修复记录；文件在设计器之外被改过时会提示
2. 修复来源厂商 .properties（只比较其中出现的模块）、项目或插件目录所需的键；也可以都不选，只处理待确认项
3. 差异与选择按模块列出新增、变化、删除的键，标出"仅类型不同"。默认勾选新增和变化，删除需要手动勾选
4. 待确认标记逐条"保留"或"确认"（写明依据），也可以新增标记；确认只去掉标记，不改数据
5. 视图与检查外设、核、引脚表的同步结果；修复前后的完整性分为已解决、仍存在、新出现
6. 保存填写来源、说明、版本（预填下一个版本）、修改人（预填 git config user.name）。保存时备份为 <芯片>.yaml.bak，并在 history/<芯片>.yaml 追加一条修改记录

向导打开期间，如果文件被设计器或别人改过，保存会被拦下并提示重新打开，不会覆盖别人的修改。向导只修改芯片库；如果项目的 chips/ 里存有这颗芯片的副本，修复后会提示用项目属性里的 Update from Library 同步。同样的修复也可以用命令行 python -m tools.chip_repair 完成，见 doc/chip_ecu_resources.md。

05影响了什么

芯片 YAML 是一颗芯片在本工具里的唯一数据源。改动它，会影响下面五个地方。

代码生成

模板和 xdm 中 ecu:get('OsResource.NumOfCores') 这类调用的结果。生成前会重新解析一次 ECU 资源再交给生成器。缺键不会阻断生成，但对应位置会静默得到空值。

配置界面的参数约束

由 ecu:get 算出的参数最大值、枚举范围和容器实例数上限，取自同一份 ECU 资源，与生成结果一致。只有芯片 YAML、没有任何 .properties 的项目，约束同样完整。

模块定义的可选值

选择器取值会并入 Resource.ResourceSubderivative 等参数的枚举，新芯片不用改 .xdm 就能被选中。已加载的模块要重新加载才能看到新值。

硬件映射结果

生成哪些容器、生成多少个、叫什么名字，都跟着外设实例和引脚表走，例如 CanConfigSet/CanController_CAN_CONTROLLER_00。改了 resource_id，新映射出的容器名会随之改变。

项目诊断

缺失键、未引用键、一致性规则、选择器与配置不符、校验和不符、芯片库有新版本，都会写入日志并在状态栏给出摘要。

已有项目

保存到芯片库不会改动已有项目，项目用的是自己 chips/ 下的副本。要同步，在项目属性点 Update from Library，它会先列出有差异的键请你确认。

项目的 ECU 资源怎么算出来。先合并插件目录里的 .properties，再合并所选芯片的 YAML，同名键以 YAML 为准并记 INFO 日志。

什么时候重新计算。新建项目、打开项目、导入 EB 项目、添加模块、更换芯片时整体重算，生成代码前还会再算一次。

07已知限制

  • 不能从引脚表生成 Port.InputModes*、Port.OutputModes* 等模式列表，这些键需要从 .properties 导入。
  • 外设推导只覆盖上表的九种类型。PWM、ICU 等需要在第 2 页手工维护。
  • 硬件映射向导的 Intc 页默认勾选全部中断源，THA6412 按默认设置会生成 942 个中断源容器。只配置用到的中断时，请先取消勾选。
  • 所需键扫描只认字面量，拼接出来的键扫不到，结果仅供参考。
  • 选择器的可选值在解析模块定义时确定。新增或更换芯片后，已加载的模块要重新加载才能看到新值。
  • Os 模板只定义了 OS_CORE_ID_0 和 OS_CORE_ID_1，4 核芯片的 2 号和 3 号核在模板里没有定义。这是模板问题，不在设计器范围内。
  • 校验和只用来发现改动，不能防止恶意篡改。
